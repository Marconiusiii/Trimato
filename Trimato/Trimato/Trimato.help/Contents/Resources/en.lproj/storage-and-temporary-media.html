Trimato Help

Understand storage and temporary media

Trimato uses original media, reusable playback copies, and short-lived render files for different jobs. Settings reports only the reusable playback copies.

Know what a project saves

A Trimato project saves your editing choices and references to the original audio and video files. It does not copy those original files into the project.

Keep every original file available. A playback proxy or temporary render is not a backup and cannot replace a missing original during final export.

Use original media directly

Trimato uses an original file for playback when macOS can play it. This is why you can do substantial editing while Settings continues to report zero playback proxy storage.

If the original can play but needs conversion for export, Trimato still uses the original while you edit and performs the required conversion during export.

Understand playback proxies

If macOS cannot play an original file directly, Trimato creates a playback proxy. A playback proxy is a compatible editing copy used for project preview and clip editing. It leaves the original unchanged.

Playback proxies are stored in macOS Caches and can be reused after a project closes. Trimato can recreate a missing or cleared proxy when the original file is available.

If the original file's size or modification date changes, Trimato stops using the old proxy and creates one that matches the changed original.

Trimato allows up to 10 GB for playback proxies. When the limit is exceeded, Trimato removes the least recently used proxies first. It also tries to keep at least 10 GB of disk space available before creating another proxy. Proxies being used by an open project or editor are retained.

macOS may remove cached files when storage is low. This is safe because Trimato can recreate them from the originals.

Review playback proxy storage

  1. Choose Trimato > Settings.
  2. Move to Playback proxy storage.
  3. Read Storage used, Proxy files, Storage limit, and Stored in.
  4. Activate Refresh storage usage when you want Trimato to read the folder again.

The reported size does not include projects, original media, completed exports, transition renders, audio previews, export intermediates, or Xcode build files.

Clear playback proxies

Clear proxies not used recently
Removes playback proxies that have not been used in the last seven days.
Clear all playback proxies
Removes every playback proxy except those required by an open project or editor.

Both commands leave original media, projects, and completed exports unchanged. Trimato recreates a cleared proxy when it is needed again and the original remains available.

Understand temporary renders

Some edits need a new file before Trimato can play the result. Trimato temporarily renders video transitions, audio transitions, and adjusted clip audio for the current preview. These files are stored separately in macOS temporary storage. They support the open editor; they are not reusable playback proxies and do not count toward the 10 GB proxy limit.

Final export can also require a temporary full-quality copy when macOS cannot use an original directly. Trimato creates that copy for the export and does not add it to the playback proxy total.

Know when temporary renders are removed

  • Rebuilding a project preview removes the files used by the previous preview.
  • Cancelling or failing a preview rebuild removes the new files created by that attempt.
  • Replacing or closing an adjusted-audio preview removes its temporary audio file.
  • Closing a project normally removes the transition, effect, and conversion files supporting its preview.
  • Finishing, cancelling, or failing an export removes the temporary files created for that export.

After an unexpected shutdown

If Trimato, Xcode, or macOS stops the app abruptly, normal closing code may not run. macOS can remove files from the temporary folder later. Trimato also removes abandoned full-quality export preparation files older than one day when it prepares another such file. Trimato does not currently perform the same startup scan for abandoned transition or adjusted-audio renders.

Generated and filtered media

Generator definitions are part of the project. Their disposable playback files are stored in the application cache and regenerated when missing. Filter preparation uses temporary media that is removed when its preview or export is released. Long sources require additional preparation time and disk space. Existing playback proxy cache totals do not include generator playback files or filter intermediates.
